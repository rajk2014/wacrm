## [17:29] - Fix Permission Denied for Accounts and WhatsApp Config Tables

- **Issue:** PostgreSQL returned `permission denied for table accounts` and `permission denied for table whatsapp_config` during authenticated queries and account context resolution. The `authenticated`, `service_role`, and `anon` database roles lacked table-level DML grants on public schema tables.
- **Root Cause:** In the linked Supabase database, public schema tables (except `profiles`) only possessed `REFERENCES, TRIGGER, TRUNCATE` privileges for `authenticated` and `service_role`. When PostgREST received queries from users or services, Postgres rejected them at the table privilege check before RLS policies could be evaluated.
- **Changes:**
  - Created migration [2026_09_27_1727_permissions_grant_table_access.sql](file:///home/amolnaik/Projects/PolicyDesk/wacrm/supabase/migrations/2026_09_27_1727_permissions_grant_table_access.sql) adhering to migration naming, idempotency, strict splitting, and RLS enforcement rules:
    - Granted schema usage on `public` to `anon`, `authenticated`, and `service_role`.
    - Granted `SELECT, INSERT, UPDATE, DELETE` on all tables in `public` to `authenticated`.
    - Granted `ALL` on all tables in `public` to `service_role`.
    - Granted `SELECT` on all tables in `public` to `anon` (strictly disallowing public write access, leaving read visibility controlled by table RLS policies).
    - Granted sequence access to `authenticated`, `service_role`, and `anon`.
    - Re-applied `REVOKE UPDATE` on `notifications` and restricted updates to column `(read_at)` for `authenticated` (preserving migration 027 column-level security).
    - Configured `DEFAULT PRIVILEGES` on `public` for future tables and sequences.
  - Applied migration to the remote linked database via `supabase db push`.
- **Validation:**
  - Verified role table grants via `information_schema.role_table_grants` on `accounts`, `whatsapp_config`, and `contacts`.
  - Verified column-level privileges on `notifications`.
  - Executed CI schema smoke test [verify-schema.sql](file:///home/amolnaik/Projects/PolicyDesk/wacrm/supabase/ci/verify-schema.sql) successfully.
  - Tested PostgREST REST API requests against `accounts` and `whatsapp_config` using service-role and anon credentials. Confirmed queries succeed without permission errors and public write attempts are rejected.
  - Ran full test suite (`npm test`) — all 86 test files and 1,015 tests passed.
